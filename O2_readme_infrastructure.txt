Benchmark Infrastructure

Following the sampling process, we constructed a folder-based benchmark infrastructure to support repair evaluation on the selected PRs. Since the our sample contains multiple PRs from the same application, the infrastructure is organized first by application and then by issue. Each application is stored under an apps/ directory using a folder name derived by concatenating the GitHub repository owner and repository name. Within each application folder, each sampled PR is stored as a separate issue directory named using its PR identifier. This structure allows multiple repair tasks from the same application to be grouped together while keeping each PR-level repair case separate.

For each sampled PR, the infrastructure script parses the GitHub PR link to identify the repository owner, repository name, and PR number. It then queries the GitHub API to retrieve PR metadata, including the PR title, database ID, merge status, merge commit SHA, and the corresponding base.sha and head.sha commits. We treat base.sha as the buggy version of the project and head.sha as the developer-fixed version. These metadata are stored in an issue.json file inside each issue directory, making each repair case traceable to its original PR and commit pair.

Each issue directory contains separate folders for the buggy version, fixed version, generated repairs, prompts, reports, scripts, and environment files. The buggy and fixed versions are downloaded as GitHub commit archives rather than full Git clones. This avoids storing .git history for each project version and substantially reduces disk usage. The generated/ directory is further separated by repair agent, such as Claude, Gemini, and Copilot, so that outputs from different Code LLMs can be stored and compared independently. The reports/ directory stores build results and manual validation outcomes. Overall, this infrastructure preserves each sampled PR as a reproducible app-issue repair workspace while keeping the storage and setup cost manageable for the full benchmark.
